# Регламент работы менеджеров с YBCRM и СДЭК

## 1. Главное правило

- Один заказ YBCRM соответствует одной действующей накладной СДЭК.
- Номер заказа YBCRM является номером ИМ в СДЭК и не меняется вручную.
- Нельзя создавать дубль с похожим номером для обхода ошибки.
- Перед удалением, изменением доставки или отказом сервер получает актуальный статус непосредственно из СДЭК.
- Данные CRM меняются только после успешного ответа СДЭК.

## 2. Разрешённые операции

| Фактическое состояние СДЭК | Разрешено |
| --- | --- |
| Накладная создана, но посылка не передана | Изменение или удаление существующей накладной |
| Посылка принята СДЭК / в пути / готова к выдаче | Отдельная смена адреса или ПВЗ; при необходимости окончательный отказ с возвратом |
| Получена / удалена / возвращена | Изменения, удаление и повторный отказ запрещены |

Удаление заказа с активной неотправленной накладной выполняется в строгой последовательности: СДЭК подтвердил удаление накладной → CRM мягко удаляет заказ. При ошибке СДЭК заказ остаётся в CRM.

## 3. Ответственность за оплату

- CRM не может запретить СДЭК выдать посылку только на основании статуса оплаты в Точка Банке.
- Для реального требования оплаты при выдаче менеджер до отправки включает наложенный платёж на сумму остатка.
- После полной онлайн-оплаты наложенный платёж снимается до выдачи, чтобы исключить повторную оплату.
- Менеджер отвечает за сумму наложенного платежа, упаковщик перед передачей сверяет номер заказа, получателя, адрес и наличие наложенного платежа.
- Продление хранения не является запретом выдачи и оформляется отдельно через СДЭК; услуга может быть платной.

## 4. Возврат

- Команда «Отказ и возврат посылки» применяется только когда действительно требуется вернуть отправление.
- Перед отправкой команды CRM показывает подтверждение и проверяет живой статус СДЭК.
- После принятия команды заказ переводится в «Возврат», а операция записывается в аудит.

## 5. Ошибки и ответственность

- Нельзя создавать дубль заказа, менять номер ИМ или вручную обходить отказ API.
- При ошибке сотрудник обновляет статус, повторяет операцию один раз, сохраняет номер заказа и текст сообщения и обращается к администратору.
- До устранения расхождения фактическим считается состояние в личном кабинете СДЭК.
- Значимые операции (изменение доставки, удаление накладной, отказ, изменение наложенного платежа) должны оставаться в аудите CRM.
