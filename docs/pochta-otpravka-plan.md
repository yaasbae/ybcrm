# Почта России в YBCRM

Предлагаемый первый выпуск — внутренние посылки по России. Сотрудник открывает заказ, выбирает Почту России, проверяет получателя, индекс, адрес, вес и размеры упаковки, получает расчёт и явно подтверждает создание отправления. После оформления видит трек-номер и скачивает ярлык. Передача электронной формы в отделение и автоматические уведомления требуют отдельного решения.

## Связь с CRM

- Карточка заказа и экран интеграций служат точками входа. В проекте уже есть отдельные операции СДЭК в `server.ts`, экран `src/components/CdekPage.tsx` и настройки в `src/components/IntegrationsPage.tsx`. Почта получает собственные серверные операции и отдельную связь с заказом, чтобы сохранённые накладные СДЭК продолжили открываться.
- Сервер читает заказ по идентификатору, проверяет право конкретного сотрудника на операцию и валидирует введённые данные. Для адреса используется нормализация из API «Отправки». Если ответ требует уточнения, сотрудник корректирует адрес перед оформлением.
- Токен приложения и ключ пользователя хранятся в серверном менеджере секретов. Первую проверку подключения выполнить запросом чтения текущих точек сдачи. Сверить доступный продукт и точку сдачи с договором. Вес передавать в граммах, размеры и денежные значения преобразовывать по схеме выбранного метода.
- До создания сохранить стабильную ссылку на заказ CRM и зафиксировать попытку в транзакции Firestore. При повторном нажатии вернуть уже созданное отправление или показать, что запрос обрабатывается. Если ответ потерян, свериться с поиском заказов у Почты перед любым повтором. При неоднозначном результате показать сотруднику статус «Требуется сверка». Отдельно сохранять ID заказа у Почты, партию и ШПИ по мере их получения. Успешное создание заказа у Почты и физическая сдача в отделение — разные события.
- Для первого выпуска предусмотреть ручное включение для согласованных ролей. Выгрузку ярлыка выполнять через сервер после проверки доступа к заказу. В аудит-логе хранить идентификаторы и результат операции без адресов, телефонов и ключей.

## Проверка перед пилотом

1. На подменённом API проверить расчёт, отказ при неверном адресе, недоступность Почты, двойное нажатие и тайм-аут после принятия запроса Почтой.
2. Проверить, что сотрудник без нужных прав, анонимный запрос и запрос по чужому заказу не могут оформить отправление или скачать ярлык.
3. После настройки секретов проверить чтение точек сдачи. Для проверки записи согласовать один контрольный заказ, сверить расчёт с кабинетом «Отправки», получить один трек-номер и открыть ярлык на desktop и mobile.
4. Для отката выключить оформление новых отправлений в CRM и сохранить ссылки на ранее оформленные. Статус уже переданного отправления сверять в кабинете Почты.

Перед разработкой согласовать объём первого выпуска и подтвердить, какой продукт и точка сдачи доступны по договору. План исходит из доставки по России без наложенного платежа. Формирование партий, получение ШПИ и выдачу ярлыка сверить по выбранному продукту, поскольку это разные операции спецификации.

## Проверка подключения в CRM

На сервере CRM задайте `POCHTA_ACCESS_TOKEN` (токен приложения) и `POCHTA_USER_KEY` (ключ пользователя в формате «Отправки», без префикса `Basic`). После запуска сервера владелец CRM может открыть «API и интеграции» → «Почта России» → «Проверить подключение». CRM проверяет доступ чтением списка точек сдачи и возвращает только состояние подключения.

Форма «Проверить и сохранить» принимает токен приложения, логин и пароль API «Отправки». Для её включения задайте `POCHTA_SETTINGS_SECRET` в формате `projects/PROJECT_ID/secrets/SECRET_ID`. Создайте выделенный секрет и предоставьте сервисному аккаунту CRM права Secret Accessor и Secret Version Adder только на этот секрет. Сервер проверяет ключи через API Почты перед сохранением и записывает токен и сформированный ключ. Пароль в исходном виде и данные из хранилища в браузер не возвращаются.
